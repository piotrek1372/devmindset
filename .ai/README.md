# DevMindset memory · P0

This is the compact entry point for project context. Read only what the task needs; verify changing facts against the live site and repositories. `FACT` describes inspected evidence; `PROVISIONAL` is a working rule awaiting owner approval; `UNKNOWN` must not be filled by guesswork. Links and observations are a snapshot, not a substitute for fresh inspection.

| Task | Read |
| --- | --- |
| Write or revise an article | `project/overview.md`, `project/audience.md`, `content/strategy.md`, `content/voice-and-style.md`, `content/source-policy.md`, `workflows/article.md`, `quality/content.md` |
| Create or change a runnable example | `project/sources-of-truth.md`, `content/code-examples.md`, `workflows/code-example.md`, `quality/examples.md`, relevant article and example code |
| Resolve a source conflict | `project/system-map.md`, `project/sources-of-truth.md` |
| Plan or triage | `state/current.md`, `state/known-issues.md` |
| Maintain this memory | `quality/memory.md`, then only the affected files |

Before editing, check for newer owner instructions. After work, update state only if its meaning changed. Create a durable lesson only for a repeated or generalizable failure. Do not manufacture an ADR or lesson to fill a folder.
