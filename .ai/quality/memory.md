# Memory maintenance

Keep this tree short and evidence based. Label `FACT`, `PROVISIONAL` and `UNKNOWN` where authority matters. Link to the authoritative source instead of copying changing article text or example code. Record observation dates for mutable repository or site facts.

When work reveals a durable decision, record who decided it, the date, alternatives and consequences before treating it as policy. When a failure generalizes beyond one fix, record the trigger, cause, correction and recurrence guard as a lesson. Do not create empty decision/lesson folders or duplicate the issue tracker. Update `state/` only when the actual state changes.

Review the task router when files are added or renamed. Confirm paths, links and source boundaries after each memory edit. Explicit owner instructions supersede provisional rules.
